Theorem

Theorem: Our implementation of an \(n\) item binary tree has _______ null pointers.

\(n + 1\). Count it: the picture has 6 nodes and 7 null pointers.

Proof: there are \(2n\) pointer fields in all. Every node except the root has exactly one pointer aimed at it, so \(n - 1\) of them are used. That leaves \(2n - (n - 1) = n + 1\) null.

Practice 1

  1. Draw a FULL tree with 9 nodes. Is it the same as your neighbour’s?

Give them a minute with a neighbour. It needn’t be the same — there are several full binary trees with 9 nodes. Every one has 4 internal nodes and 5 leaves, though: in a full binary tree, leaves = internal + 1.

Practice 2

  1. Draw a COMPLETE tree with 12 nodes. Is it the same as your neighbour’s?

This time it is the same as your neighbour’s: a complete tree’s shape is fixed by its size. Levels of 1, 2, 4, and then 5 nodes on the bottom level, filled from the left.

Practice 3

3a) Give an upper bound for the number of nodes in a tree of height h:



3b) Give a lower bound for the height of a tree containing n nodes:

3a) At most a perfect tree: \(n \le 2^{h+1} - 1\).

3b) Turn it around: \(2^{h+1} \ge n + 1\), so \(h \ge \log_2(n+1) - 1\). A binary tree with \(n\) nodes has height \(\Omega(\log n)\) — this will matter for every search tree we build.

Practice 4

  1. Give upper and lower bounds for the number of nodes in a complete tree of height h:

Most: a perfect tree of height \(h\), \(2^{h+1} - 1\).

Fewest: a perfect tree of height \(h-1\) plus one node starting the next level: \((2^h - 1) + 1 = 2^h\).

So \(2^h \le n \le 2^{h+1} - 1\), and a complete tree’s height is exactly \(\lfloor \log_2 n \rfloor\).

Tree traversal:

… a scheme for visiting every node

Every node, exactly once — in what order? On this expression tree the three classic orders give three classic notations:

  • preorder: + - / b c * d e (prefix)
  • inorder: - b / c + d * e (infix — the expression as written)
  • postorder: b c / - d e * + (postfix, a stack machine’s order)

The - has only a right child here: it’s a unary minus.

Click into it first. 1 / 2 / 3 pick pre / in / post, P plays, → steps, T changes tree, R resets.

The pointer passes every node three times — left side, underneath, right side. Pick a pass and the node squawks there. Same walk, three orders: the only thing that changes is when you speak up. That’s the one line that moves in the code.

Ask before playing: on the a–j tree, which letter squawks third in inorder? (f: d, b, f…)

The given order is inorder: 3, 12, 9, 7, 10, 15, 30, 20, 8.

  • Preorder: 10, 12, 3, 9, 7, 15, 20, 30, 8
  • Postorder: 3, 7, 9, 12, 30, 8, 20, 15, 10

The code: one line, visit(croot) (say, cout << croot->data), goes in one of three places — before both calls (pre), between them (in), or after both (post). Same skeleton, three traversals.

Running time: each node is visited once, so \(\Theta(n)\). (The proof is next lecture.)

Traversal shortcuts… Euler tour

Draw a path that hugs the tree, starting left of the root and keeping the tree on your left-hand side. You pass each node three times: on its left (pre), underneath (in), and on its right (post). Read off the nodes at the first, second or third pass to get each order.

  • Pre: a b d f c e i j h
  • In: d b f a c i j e h
  • Post: d f b j i h e c a

Mystery function: what’s a good name?

RT:

template<class T>
void tree<T>::__________(Node * croot) {
    if (croot != nullptr) {
        __________(croot->left);
        __________(croot->right);
        delete croot;
        croot = nullptr;
    }
}

It deletes both subtrees, then the node: a postorder traversal that frees the whole tree — call it clear or destroy. It has to be post: delete the node first and croot->left is gone.

RT: \(\Theta(n)\), one visit per node.

Look at the last line: croot is a copy of the caller’s pointer, so setting it to nullptr changes nothing outside. The caller’s root still points at freed memory. Fix: take Node *& croot.

Make the node first, then its subtrees: a preorder traversal. (Building the children first and the node last — postorder — works too.) Traversal is a pattern for any whole-tree job, not just printing.
