  • Every vertex but the root has exactly one parent; the root has none.

  • Fewest children: the leaves e, f, i, j (zero).

  • d’s depth is 2 (edges from the root). d’s height is 3 (d–g–h–i). d’s level is 2 — level is depth, counting the root as level 0. (Some books start the root at level 1.)

    These three are easy to mix up. Depth is measured down from the root (how far is d from the top?). Height is measured up from the leaves (how far is d from its farthest leaf?). A level is a whole row: every node at the same depth. c and d share a level (both at depth 2), but their heights differ: c’s is 1, d’s is 3.

Tree terminology (for your reference)

  • root: the single node with no parent
  • leaf: a node with no children
  • child: a node pointed to by me
  • parent: the node that points to me
  • sibling: another child of my parent
  • ancestor: my parent or my parent’s ancestor
  • descendant: my child or my child’s descendant
  • subtree: a node and its descendants
  • depth of node x: number of edges on the path from the root to x
  • height of node x: number of edges on the longest path from x to a leaf
  • level k: all the nodes at depth k

Notice that ancestor, descendant and subtree are defined recursively — that’s where we’re headed.

A \(d\)-ary tree is either empty, OR a root node with \(d\) subtrees, each of which is a \(d\)-ary tree. Recursive, like the list.

  • Full: every node has either 0 or \(d\) children.
  • Perfect: every internal node has \(d\) children and every leaf is at the same depth. Recursively: a perfect tree of height \(-1\) is empty; of height \(h\) is a root whose \(d\) subtrees are perfect of height \(h-1\).
  • Complete: perfect down to the second-last level, and the last level is filled in from the left.

The picture is the expression \((2 \times (3 - 5)) + 4\). It’s full, but not perfect or complete.

Binary tree height

height(r) — length of the longest path from root r to a leaf

Given a binary tree T, write a recursive definition of the height of T, height(T):

Number of nodes in a perfect tree of height h, N(h):

\[\text{height}(T) = \begin{cases} -1 & T \text{ empty} \\ 1 + \max(\text{height}(T_L), \text{height}(T_R)) & \text{otherwise} \end{cases}\]

The empty tree has height \(-1\), so a single node has height \(0\). The expression tree has height 3.

\(N(-1) = 0\), \(N(h) = 2N(h-1) + 1\), so \(N(h) = 2^{h+1} - 1\).

Theorem

Theorem: Our implementation of an \(n\) item binary tree has _______ null pointers.

\(n + 1\). Count it: the picture has 6 nodes and 7 null pointers.

Proof: there are \(2n\) pointer fields in all. Every node except the root has exactly one pointer aimed at it, so \(n - 1\) of them are used. That leaves \(2n - (n - 1) = n + 1\) null.

Give them a minute with a neighbour. It needn’t be the same — there are several full binary trees with 9 nodes. Every one has 4 internal nodes and 5 leaves, though: in a full binary tree, leaves = internal + 1.

Practice 2

  1. Draw a COMPLETE tree with 12 nodes. Is it the same as your neighbour’s?

This time it is the same as your neighbour’s: a complete tree’s shape is fixed by its size. Levels of 1, 2, 4, and then 5 nodes on the bottom level, filled from the left.

3b) Give a lower bound for the height of a tree containing n nodes:

3a) At most a perfect tree: \(n \le 2^{h+1} - 1\).

3b) Turn it around: \(2^{h+1} \ge n + 1\), so \(h \ge \log_2(n+1) - 1\). A binary tree with \(n\) nodes has height \(\Omega(\log n)\) — this will matter for every search tree we build.

Practice 4

  1. Give upper and lower bounds for the number of nodes in a complete tree of height h:

Most: a perfect tree of height \(h\), \(2^{h+1} - 1\).

Fewest: a perfect tree of height \(h-1\) plus one node starting the next level: \((2^h - 1) + 1 = 2^h\).

So \(2^h \le n \le 2^{h+1} - 1\), and a complete tree’s height is exactly \(\lfloor \log_2 n \rfloor\).
