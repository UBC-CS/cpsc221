Priority Queue ADT

Fill in each row’s insert and removeMin.

  • Unsorted array: insert \(O(1)\) (amortized: \(O(n)\) when it has to grow), removeMin \(O(n)\) to find the min and fill the hole.
  • Unsorted list: insert \(O(1)\) at the front, removeMin \(O(n)\).
  • Sorted array: insert \(O(n)\) (binary search finds the spot in \(O(\log n)\), but the shift is \(O(n)\)), removeMin \(O(1)\) if it’s sorted largest-first, so the min is at the end.
  • Sorted list: insert \(O(n)\) (no binary search on a list), removeMin \(O(1)\) from the front.

Every option is \(O(n)\) somewhere. Can we get both down to \(O(\log n)\)?

Priority Queue: another implementation option

Tell me everything you can about this structure:

Describe its implementation…

  • Binary tree, complete: every level full except possibly the last, which fills left to right.
  • Heap property (min-heap): every node’s key is \(\le\) its children’s. So the min is at the root.
  • No left/right order between siblings: this is not a BST.
  • Height \(\lfloor \log_2 n \rfloor\), because it’s complete.

Implementation: the colours are a hint. Complete means no gaps, so read it level by level into an array.

(min)Heap: implementation

Root at index 1 (index 0 left empty).

For the node at index \(i\):

  • left child \(2i\)
  • right child \(2i + 1\)
  • parent \(\lfloor i/2 \rfloor\)

No pointers at all: the shape is the arithmetic.

(min)Heap: insert

The box is size; the three empty cells are spare capacity.

Try insert(5): it goes in the next free slot, index 13 (right child of 7). Then swap upward while it’s smaller than its parent: past 7, past 6, and it stops under 4. Repeat with insert(3) to reach the root.

\(O(\log n)\): at most one swap per level.

Code:

void heap<T>::insert(const T & key) {
    if (size == capacity) growArray();
    size++;
    items[size] = key;
    heapifyUp(size);
}

growArray()

When the array is full: double the capacity and copy. The new last level needs as many slots as the whole tree so far. Doubling makes insert amortized \(O(1)\) for the growing, plus \(O(\log n)\) for heapifyUp.

Code:

void heap<T>::insert(const T & key) {

    size++;
    items[size] = key;
    heapifyUp(size);
}
void heap<T>::heapifyUp(int cIndex) {
    if (cIndex > _____)
        if (items[cIndex] ___ items[parent(cIndex)]) {
            swap(__________, __________);
            heapifyUp(__________);
        }
}
  • cIndex > 1: stop at the root
  • items[cIndex] < items[parent(cIndex)]
  • swap(items[cIndex], items[parent(cIndex)])
  • heapifyUp(parent(cIndex))

(min)Heap: removeMin

The min is the root. What fills the hole and keeps the tree complete? Only the last leaf can move without leaving a gap: 11 goes to the root.

Then swap it downward with its smaller child while it’s bigger: 11 swaps with 5, then with 9, and stops: its new children, 14 and 12, are both bigger.

\(O(\log n)\).

(min)Heap: removeMin

A clean copy for a second removeMin, or for a student to try.

Code:

T heap<T>::removeMin() {
    T minVal = items[1];
    items[1] = items[size];
    size--;
    heapifyDown(1);
    return minVal;
}
void heap<T>::heapifyDown(int cIndex) {
    if (hasAChild(cIndex)) {
        minChildIndex = minChild(cIndex);
        if (items[cIndex] ___ items[minChildIndex]) {
            swap(__________, __________);
            ___________________________
        }
    }
}
  • items[cIndex] > items[minChildIndex]
  • swap(items[cIndex], items[minChildIndex])
  • heapifyDown(minChildIndex);

Why the min child? Swapping with the larger one would put it above the smaller one, breaking the heap property right there.
