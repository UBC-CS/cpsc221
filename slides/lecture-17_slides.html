Traversal — running time

\(T(n)\): running time of a traversal on a tree with \(n\) nodes.

\(T(0) = 1\)

\(T(n) = T(n_L) + T(n_R) + 1,\; n > 0.\)

Thm: \(T(n) = 2n + 1,\; n \ge 0.\)

template<class T>
void tree<T>::preOrder(Node * croot) {
    if (croot != nullptr) {
        cout << croot->data;
        preOrder(croot->left);
        preOrder(croot->right);
    }
}

\(n_L\) and \(n_R\) are the sizes of the left and right subtrees, so \(n_L + n_R = n - 1\). Note \(T(0) = 1\): calling on an empty tree still costs one check.

Proof, by strong induction on \(n\).

Base case, \(n = 0\): \(T(0) = 1 = 2 \cdot 0 + 1\). ✓

IH: \(T(j) = 2j + 1\) for all \(j < n\).

Step, \(n > 0\): both subtrees are smaller than \(n\), so

\[T(n) = (2n_L + 1) + (2n_R + 1) + 1 = 2(n_L + n_R + 1) + 1 = 2n + 1.\]

Where does the “\(+1\)” come from? The \(n + 1\) calls on empty subtrees — the null pointers from Monday’s theorem. \(n\) real calls plus \(n + 1\) empty ones is \(2n + 1\). Any traversal is \(\Theta(n)\).

Level order: + - * / d e b c. Top to bottom, left to right — so it can’t follow the recursion. It needs a queue.

  1. Make a queue; enqueue the root (if it isn’t null).
  2. While the queue isn’t empty:
    1. dequeue a node, t;
    2. visit t, then
      1. enqueue t->left if it isn’t null;
      2. enqueue t->right if it isn’t null.
Queue<Node *> q;
if (croot != nullptr) q.push(croot);
while (!q.isEmpty()) {
    Node * t = q.pop();
    cout << t->data;
    if (t->left  != nullptr) q.push(t->left);
    if (t->right != nullptr) q.push(t->right);
}

This is PA2. components() and computeDistances() are this loop, with “neighbours on the map” in place of “children”. Enqueue something only the first time you see it — a map, unlike a tree, can lead you back to a node.

More examples of key/value pairs:

  • CWL → Advising record
  • Course number → Schedule info
  • Color → PNG
  • Vertex → Set of incident edges
  • Flight number → Arrival information
  • URL → html page


A dictionary is a structure supporting:

void insert(kType & k, dType & d)
void remove(kType & k)
dType find(kType & k)

Keys are unique; each one maps to its data. Every example on the right is a real system’s core: a CWL lookup, a flight board, the web itself.

ADT Dictionary: implementation options…

insert find (find +) remove
linked list \(\Theta(1)\) \(\Theta(n)\) \(\Theta(n) + \Theta(1)\)
unsorted array \(\Theta(1)\) \(\Theta(n)\) \(\Theta(n) + \Theta(1)\)
sorted array \(\Theta(\log n) + \Theta(n)\) \(\Theta(\log n)\) \(\Theta(\log n) + \Theta(n)\)
Binary Tree?

Linked list and unsorted array: insert anywhere, but find has to look at everything. Sorted array: binary search finds in \(\log n\), but inserting and removing shift everything over. Nothing is fast at all three.
