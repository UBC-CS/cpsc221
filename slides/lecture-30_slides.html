(2024’s example. Each student is a number; each oval is one set of the partition, one per favorite.)

  1. Which set is 4 in? Find returns that set’s representative, one member that names the set.
  2. Are 4 and 8 in the same set? Same representative.
  3. If 7 and 2 are in different sets, merge the two sets.

Disjoint Sets ADT

We will implement a data structure in support of “Disjoint Sets”:

  • Maintains a collection \(S = \{s_0, s_1, \ldots, s_k\}\) of disjoint sets
  • Each set has a representative member
  • Supports functions:
void MakeSet(kType k);
void Union(kType k1, kType k2);
kType Find(kType k);
  • MakeSet: a new set holding just k.
  • Union: merge the sets containing k1 and k2.
  • Find: the representative of k’s set.

From here on the keys are 0..n-1, so they can index an array.

Each cell holds its key’s representative.

  • Find: \(O(1)\), one array lookup.
  • Union: \(O(n)\). Every member of one set has to be relabelled, and finding them means scanning the whole array.

Unions are the common operation (Kruskal’s algorithm does one per edge it keeps), so we want something cheaper.

A better data structure: UpTrees

  • If the array value is \(-1\), we’ve found a root; otherwise the value is the index of the parent.
  • \(x\) and \(y\) are in the same tree if and only if they are in the same set.

Start: four singleton sets, every cell \(-1\).

A sequence to draw (Union takes two roots; root2 goes under root1):

  • Union(2, 3): 3 points to 2. Array: \(-1, -1, -1, 2\)
  • Union(0, 1): 1 points to 0. Array: \(-1, 0, -1, 2\)
  • Union(0, 2): 2 points to 0. Array: \(-1, 0, 0, 2\)

Find(3) now walks 3 → 2 → 0: the representative is the root.

What’s an ideal tree?

void DS::Union(int root1, int root2) {
    s[root2] = root1;
}




  • Find’s running time depends on the height of the tree (the depth of i).
  • Worst case: \(O(n)\), a stick. The picture: Union(1, 0) would hang 0 under 1 and make the stick even longer for nothing, while Union(0, 1) hangs the stick under 0, making every node in it one step deeper.
  • Ideal tree: every node points straight at the root (height 1), so Find is \(O(1)\).

Union itself is \(O(1)\), given two roots. The cost moved into Find.

Smart unions

Both of these schemes for Union guarantee the height of the tree is ____________.

A root’s cell is free to hold something useful, as long as it stays negative (that’s how Find recognizes a root):

  • By height: store \(-(h+1)\), so a lone node is still \(-1\). 7 holds \(-3\) (height 2) and 4 holds \(-4\) (height 3). Union hangs the shorter tree under the taller: 7 goes under 4, and the height stays 3.
  • By size: store \(-(\text{number of nodes})\). 7 holds \(-9\), 4 holds \(-4\). The smaller tree goes under the bigger: 4 goes under 7. Height becomes 4, but only 4 nodes got one step deeper, instead of 9.

Either way the height is \(O(\log n)\): a node only gets deeper when its tree at least doubles in size, which can happen at most \(\log_2 n\) times.

Smart unions

int DS::Find(int i) {
    if (s[i] < 0) return i;
    else return __________ Find(s[i]);
}
void DS::UnionBySize(int root1, int root2) {
    int newSize = s[root1] + s[root2];
    if (isBigger(root1, root2)) {
        s[root2] = root1;
        s[root1] = newSize;
    }
    else {
        s[root1] = root2;
        s[root2] = newSize;
    }
}

isBigger(root1, root2): root1’s tree is at least as big. Sizes are stored negative, so that’s s[root1] <= s[root2]. Ties go to root1, the first argument, which is PEX9’s rule too.

The blank in Find: s[i] =, so line 3 reads else return s[i] = Find(s[i]);. Annotate it here; that’s path compression, next slide.

Path compression


On the way back from the root,
every node on the path is
pointed straight at the root.

Nodes off the path (1, 8, 3, 6)
just come along with their parents.

The next Find on any of them
is one or two steps.

(Cinda’s example, from DSCI 221.) Find(5) walks 5 → 4 → 2 → 7 → 9 → 10. On the way back, the assignment points each node on that path (yellow) straight at 10.

Only the path changes. 1, 8, 3 and 6 aren’t on it, so they stay with their parents and simply come along: 8 still hangs off 7, 3 off 2, 6 off 4. 11 doesn’t move at all. Every one of them is now closer to the root too.

Path compression doesn’t change sizes, so union by size works with it unchanged. With union by height, the stored heights are no longer exact after compression (they’re upper bounds), and that’s fine.

Analysis

Something we’ll need — Iterated log:

\[\log^* (n) = \begin{cases} 0 & \text{if } n \leq 1 \\ 1 + \log^*(\log n) & \text{if } n > 1 \end{cases}\]

Example: \(\log^* (2^{65536})\)

Relevant result: In an upTree implementation of Disjoint Sets using
smart Union and Find with path compression, any sequence of \(m\) Union
and Find operations results in worst case running time of \(O(\_\_\_\_\_\_\_\_\_\_)\),
where \(n\) is the number of items.

http://research.cs.vt.edu/AVresearch/UF/

(Cinda’s slide, from DSCI 221.)

\(\log^*(2^{65536})\): \(2^{65536} \to 65536 \to 16 \to 4 \to 2 \to 1\), five logs, so 5. \(2^{65536}\) has about 20,000 digits; nothing we will ever store comes close, so \(\log^* n \le 5\) in practice.

The blank: \(O(m \log^* n)\). That’s essentially \(O(m)\), constant time per operation. PEX9 asks for exactly this.

The proof is beyond this course. (The tight bound is even smaller, inverse Ackermann, \(O(m\,\alpha(n))\).)
