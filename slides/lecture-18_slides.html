Binary search tree

A Binary Search Tree (BST) is a binary tree, T, such that:

  • ____________, OR

  • T = {r, TL, TR} and

    x ∈ TL → ______________

    x ∈ TR → ______________

and

  • T is empty, OR
  • T = {r, T_L, T_R} and
    • x ∈ T_L → x.key < r.key
    • x ∈ T_R → x.key > r.key
  • and T_L and T_R are BSTs.

The “and” matters: checking only each node against its own children is not enough. 37 sits right of 25 — fine — but it must also be less than 38, because it’s in 38’s left subtree.

Three nodes have lost their keys. What could each one be? The left child of 13 must be less than 13; the right child of 25 must be between 25 and 38; the left child of 84 between 51 and 84. A key’s position constrains it from every ancestor.

Each node now carries a key (what we search by) and data (what we want back) — the locker number and the name.

Binary search tree — insert

What if key == croot->key?


Running time:

template<class K>
void insert(Node * croot, const K & key) {

    if (croot == nullptr)
        croot = new Node(key);

    else if (key < croot->key)
        insert(croot->left);

    else if (key > croot->key)
        insert(croot->right);
}

Insert 95 (or any key): walk down as if finding it, and hang the new node where the search falls off the tree.

key == croot->key: the key is already there. Either do nothing, or replace the data — keys are unique.

Running time: Θ(h), one step per level, where h is the height.

Does this code work? Two problems:

  1. croot is passed by value. croot = new Node(key) changes the copy; the parent’s pointer is still null and the new node leaks.
  2. insert(croot->left) forgets the key.
void insert(Node *& croot, const K & key) {   // & on the pointer
    if (croot == nullptr) croot = new Node(key);
    else if (key < croot->key) insert(croot->left, key);
    else if (key > croot->key) insert(croot->right, key);
}

Why return Node *&? It hands back the pointer itself — the parent’s left or right, or root. If the key isn’t there, that pointer is the null one where the key belongs, so insert becomes Node *& p = find_(key, root); if (p == nullptr) p = new Node(key, data);.

Running time: Θ(h).

In the explorer: Delete 37, then 51.

  • 37 is a leaf: just remove it. Its parent’s pointer becomes null.
  • 51 has one child (84): splice it out — 38’s right pointer now points at 84. Everything under 84 is still bigger than 38, so the tree is still a BST.

Binary search tree — remove

void BST<K>::zeroOneChildRemove(Node * & cRoot) {
    Node * temp = cRoot;
    if (cRoot->left == nullptr) cRoot = cRoot->right;
    else cRoot = cRoot->left;
    delete temp;
}

cRoot is a reference to the parent’s pointer, so reassigning it splices the node out. If the left child is null, the right child (possibly also null — the leaf case) moves up; otherwise the left does. Then free the old node. Both the zero- and one-child cases in five lines.

What’s left?

  • find and insert are Θ(h). For n keys, h is somewhere between \(\log n\) (bushy) and \(n - 1\) (a stick — insert keys in sorted order). So: \(O(\log n)\) if we’re lucky, \(O(n)\) if we’re not.
  • Inorder visits the keys in sorted order.
  • remove (so far) is Θ(h) too.
  • Left: removing a node with two children (next time), and keeping the tree short so we’re always lucky.
