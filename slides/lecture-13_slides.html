Where we left off

merge two sorted halves into one sorted array: \(\Theta(n)\).

Split in half, sort each half, merge. But how do the halves get sorted?

Recap from Wednesday. Merge walks a finger along each half and copies the smaller item each time; every item is copied once, so it’s linear.

The question we left hanging: the halves. Answer: the same way. Sort each half by splitting it in half…

mergeSort

  1. If the array has 0 or 1 elements, it’s sorted.
  2. Split the array into halves.
  3. Sort each half recursively.
  4. Merge the two halves.
void mergeSort(vector<T> & A, int lo, int hi) {
    if (hi > lo) {
        int mid = (hi + lo)/2;
        mergeSort(A, lo, mid);
        mergeSort(A, mid+1, hi);
        merge(A, lo, mid, hi);
    }
}

RT:

Write the recurrence beside RT. With \(T(n)\) the time to sort \(n\) items:

\[T(1) = b, \qquad T(n) = 2\,T(n/2) + cn\]

Two recursive calls on half the input, plus a linear merge. The split itself is constant. Assume \(n\) is a power of 2 so the halves are exact.

Closed form 1: expand and generalize

\(T(n) = 2\,T(n/2) + cn, \quad T(1) = b\)

\[ \begin{aligned} T(n) &= 2T(n/2) + cn \\ &= 4T(n/4) + 2cn \\ &= 8T(n/8) + 3cn \\ &\;\;\vdots \\ &= 2^k\,T(n/2^k) + kcn \end{aligned} \]

The base case is reached when \(n/2^k = 1\), i.e. \(k = \log n\):

\[T(n) = n\,T(1) + cn\log n = cn\log n + bn.\]

Closed form 2: recursion tree

Each level does a total of \(cn\) work: one \(n\), two \(n/2\)’s, four \(n/4\)’s… The leaves are \(n\) base cases at \(b\) each.

The tree has \(\log n\) levels of merging, so the total is \(cn\log n + bn\) — the same answer as expanding.

Proving the closed form is correct:

Thm: \(\forall n \ge 1,\; T(n) \le cn\log n + bn.\)

By induction on \(n\) (powers of 2).

Base case, \(n = 1\): \(T(1) = b \le c \cdot 1 \cdot 0 + b \cdot 1 = b\). ✓

IH: assume \(T(j) \le cj\log j + bj\) for all \(j < n\).

Inductive step, \(n > 1\):

\[ \begin{aligned} T(n) &= 2T(n/2) + cn \\ &\le 2\left(c\tfrac{n}{2}\log\tfrac{n}{2} + b\tfrac{n}{2}\right) + cn \\ &= cn(\log n - 1) + bn + cn \\ &= cn\log n + bn. \end{aligned} \]

Claim: mergeSort correctly sorts A[lo..hi] for any (hi-lo+1) ________

Let \(n\) = (hi - lo + 1), arbitrary.

\(n \le 1\): (Base Case)

\(n > 1\): IH: Assume mergeSort correctly sorts a slice of size \(j\), for any \(j < n\).

int mid = (hi + lo)/2;

mergeSort(A, lo, mid);
mergeSort(A, mid+1, hi);

The blank: \(\ge 0\). The empty slice counts.

Base case, \(n \le 1\): hi > lo is false, nothing happens, and a slice of 0 or 1 items is already sorted.

\(n > 1\): because lo < hi, mid satisfies lo ≤ mid < hi. Why:

  • lo ≤ mid: the average of lo and something at least lo is at least lo, and rounding down can’t take it below lo, because lo is a whole number.
  • mid < hi: since lo ≤ hi − 1, the average is at most hi − ½, and rounding down keeps it below hi.

It only works because lo < hi, which is why the 0-or-1 case has to be the base case: with lo = hi, mid = hi and the first call would be the same call again.

So both A[lo..mid] and A[mid+1..hi] have at least one item and fewer than \(n\). That’s exactly what the IH needs: both recursive calls sort their halves.

  • could we do a \(k\)-way merge sort?

merge takes two sorted slices that sit side by side and produces one sorted slice of the same items. (Its own correctness is a loop invariant: the output so far is sorted and holds the smallest items seen.)

Conclusion: A[lo..hi] is sorted. Since \(n\) was arbitrary, mergeSort sorts every slice, and in particular the call mergeSort(A, 0, A.size()-1) sorts the whole array.

To contemplate:

  • Correctness: no. Any mid with lo ≤ mid < hi works — the proof only needs both halves to be smaller.
  • Runtime: yes. Split off one item at a time (mid = lo) and the recurrence becomes \(T(n) = T(n-1) + cn\), which is \(\Theta(n^2)\).
  • \(k\)-way: yes. \(\log_k n\) levels, but each merge now picks the smallest of \(k\) fronts. Still \(\Theta(n \log n)\).

Where are we in the sorting picture?

Best case Worst case
Insertion \(O(n)\) \(O(n^2)\)
Selection \(O(n^2)\) \(O(n^2)\)
Merge \(O(n\log n)\) \(O(n\log n)\)
